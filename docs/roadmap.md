## Open work

Open work is tracked as issues: [issues](https://github.com/phabioo/uzume-plugin-soullink-core/issues) and the [milestones](https://github.com/phabioo/uzume-plugin-soullink-core/milestones).

## v0.1 Omega Ruby / Alpha Sapphire (3DS, Gen 6)

- Game detection by title ID, German/EU release first, German and English at least; detect the active game language at runtime (3DS system language), never assume it.
- Adapters: team, boxes, location, battle state, encounters, badges; PKM decryption/shuffle (Gen 6) with synthetic fixtures generated by code.
- Asset extraction from the player's own game files into the local plugin cache (box icons, sprites, region map); nothing is stored in this repository.
- Location/route table keyed by internal IDs, with self-recorded map coordinates; `provides` interface for other plugins.
- Offsets documented per game in `docs/games/<game>.md`; verified locally by the maintainer with the Uzume developer mode.

### Status v0.6.0 (demo data)

- v0.7.0 (closes issue 27): `pokemon.core` `encode_item(pouch, item, count[, slot])`, `bag()` and extended `edit_limits()`. All five pouches lie behind the `bag` address (offsets 0x000, 0x640, 0x7C0, 0x970, 0xA70; slots 400, 96, 108, 64, 72), packed lists of u16 id + u16 count; the `bag` watch now covers the whole bag (0xB90 bytes). Contract v0.6. Unchecked on a real game; open: whether the TM pouch is a packed list or fixed slots, and which item belongs in which pouch (not validated).
- v0.6.4: `pokemon.core` `balls()` (SoulLink issue 46): `{ count }` = sum of the counts of all Poke Ball item ids in the Items pouch (address key `bag`, 400 slots of u16 id + u16 count; ids 1..16, 492..500, 576), `nil, "unsupported"` without a bag address or when the pouch looks like garbage. Contract v0.5. Addresses unverified on a real game (see `docs/games/omega-ruby-alpha-sapphire.md`).
- v0.6.3: field report (Core 0.6.2, soullink issue 30): the map index was reused after an update (`map_archives_scanned=0`). The index header and the PNG cache keys now carry `maps.CACHE_REV` (index format `3`, scan revision `m2`, plugin version); any other header (also the old `complete 3`) is rescanned from the directory walk. LZ limits raised to 8 MiB (1024x1024 RGBA8 is 4 MiB plus footer), `diagnostics()` has `map_rev`. Open: the real region map location and format (no candidate in the field report was the Hoenn map).
- v0.6.2: plugin API namespace `uz` (Uzume 0.22); the bundle starts with `local uz = uz or fb` so older apps keep working.
- v0.6.1: global event `badges.changed` `{ count, new }` from the ORAS adapter and the demo adapter, so plugins without a hard dependency (Splits) can react to badges.

- v0.6.0: demo adapter (`demo.adapter`, `demo.data`) for live tests without a game: synthetic team of 3, one box creature, three zones (town, two routes with encounter areas), and a timeline at 30 ticks per second (10 s route 1, 15 s wild encounter, 20 s catch, 30 s route 2, 40 s trainer battle, 45 s faint of team slot 4 (the caught creature), 50 s battle end, 60 s first badge). Names are synthetic ("Demomon N", "Demo Route 1"); icons are generated squares when `uz.codec.png` exists, otherwise `icon()` answers `nil, "unsupported"`. It runs only when the plugin store key `dev.demo_data` is `true` (the API has no per-plugin settings screen; set it with the MCP tool `store_put`, then restart the game). `info().demo` is `true`, `info().revision` is `"demo"`, `game.detected` carries `demo`. New permission `store`. No game memory is read in demo mode.

### Status v0.5.0 (ORAS)

- v0.5.0: PK6 encrypt, checksum and seal in `gen6.pk6` (pure Lua, same algorithm as `uz.codec.pk6_*`); `gen6.pk6_edit` (validation, EXP from level via the game's growth rate, nature, IVs/EVs with the 510 total, moves with PP, PID based shiny, held item, nickname, live party level/HP/stats recomputed from the personal base stats); `pokemon.core` gains `encode_pokemon(location, fields)`, `encode_money(value)`, `edit_limits()`, `names_list(kind)` and the feature flags `edit_pokemon edit_money edit_items name_lists` (contract v0.4, existing calls unchanged). The helpers only return write operations `{ addr, bytes }`; the Creature Editor plugin writes them with `uz.memory.write`.
- Limits: `encode_item` answers `nil, "unsupported"` (no bag offsets documented, none invented); a newly chosen move gets the caller's `pp`, else a placeholder of 5 plus the warning `pp_unknown`; `ability` can be set by id, a species change warns `ability_unchanged`; nothing here is verified on a real game.

### Status v0.4.1 (ORAS)

- v0.3.5: display name is now "SoulLink Core" (trademark avoidance) (manifest, i18n en/de, README); plugin id and interface unchanged (the id changed in 0.4.0).
- v0.4.2: ORAS box icons decoded as palette images (variant D, 4-bit and 8-bit indices, zero padding) and looked up through the measured icon order table (`gen6.icon_order`, numbers only); `info().icon_rev` lets consumers key their icon caches.
- v0.4.1: one-time debug export of raw icon GARC entries into the plugin cache (`diag/icon-<entry0>.bin`, `diag/icon-index.txt`) to settle whether the box icons are decoded wrongly or indexed wrongly; diagnostics key `icon_export`. Local to Fabio's PC, nothing enters the repository.
- v0.4.0: new plugin id `uzume.soullink-core` (Uzume ADR 0030 D7); no migration and no compatibility alias; the `provides` interface `pokemon.core` is unchanged.

- v0.3.4 (field report on a real Omega Ruby EUR v1.0, Player 0.15.7): (1) map scan: `step()` now runs units until a 25 ms `uz.clock` budget is used (was one unit per call, i.e. one 16-entry batch per 8 ticks), tiny entries are skipped without decompressing (LZ header size / GARC length), a throwing entry or archive is counted and skipped instead of ending the scan, the scan ends in `done` or `failed` (time limit 30 min, error limit) and `diagnostics()` has `map_*` keys; (2) icons: new `gen6.pal_bclim` (palette variants A-D, plain 16-bit texture E), `icon_variants(species, form)`, PNG cache key with decoder revision, `icon_e1_*` palette/layout diagnostics; format 7 data of exactly 64x32x2 bytes is a plain tiled RGBA5551 texture (a first pixel of 0x0002 matched the Player's palette signature); (3) the personal table is loaded by ticks (it was only loaded on demand, so `personal_attempts=0` was expected when the team carries live levels).

### Status v0.3.3 (ORAS)

- v0.3.3: format audit fixes (2026-10-18): language byte 7 = Spanish (6 unused); GARC entries with first byte 0x11 are LZ11-decompressed in text, personal and icons through the shared `gen6.garc_entry` (zones and maps use it too); `diagnostics()` gains an icon archive probe (`icons_*`, `icon_e1/e25/e700_*`), `personal_*` and `text_first_rejection`; test GARCs use the real `CRAG` magic. Open: form icon index ([#33](https://github.com/phabioo/uzume-plugin-soullink-core/issues/33)).

### Status v0.3.2 (ORAS)

- v0.3.2: `locations()` no longer stays empty (zone scan failed, unsupported or empty: every named line of the location text, `source = "text"`); lists are handed out only with names (a consumer caches the first list); failed archive opens and scans are retried slowly instead of ending in a final `unsupported` (zones and game text); new `diagnostics()` (counts, states, first rejection reason, no names).

- v0.3.1: lenient ZO pack parsing (a bad offset no longer drops the pack), table-only zones, `locations()` (all places, towns included), the archive open is retried, species list found by content when file 98 is implausible, `species_name` on encounter records/events, diagnostics log lines (counts only).

- Done in code (synthetic tests): revisions v1.0/v1.4 with address overrides, live party stats, trainer/badges/money/play time, game text names, zones and encounter areas, `species_info`, battle/encounter tracking with events, region map scan with priority archives and noise filter.
