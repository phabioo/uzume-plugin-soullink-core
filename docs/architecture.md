# Architecture

## Layout

- `src/`: Lua modules (`core/*`, `gen6/*`, `main.lua`). The module list is `src/modules.txt`.
- `tools/bundle.lua`: generates `plugin/main.lua`.
- `plugin/`: the installable plugin (`manifest.json`, generated `main.lua`, `i18n/`). `plugin/main.lua` is committed; never edit it by hand.
- `tests/`: `lua5.4 tests/run.lua` runs every `tests/test_*.lua` against a fake `fb` (`tests/support/fb_mock.lua`) with synthetic data only.

## Bundling

The Uzume sandbox has no `require`, `load`, `dofile`, `io` or `os` and loads one entry file. The bundler wraps each listed module as `__mod["core.games"] = function(...) ... end`, defines a local `require` (loads each module once, returns `nil` for unknown names) and calls `require("main")`. Output is deterministic. `lua5.4 tools/bundle.lua` writes, `--check` exits 1 when `plugin/main.lua` is stale (CI). A new module must be added to `src/modules.txt`; a listed module whose file is missing is skipped.

## Detection

`core.games` holds `GAMES` (`id, name, gen, system, codes, version, adapter`). `detect(fb.game)` returns `entry, info` or `nil`.

- 3DS: exact, case-insensitive match of the title ID. Title IDs are the same for all languages, so `info.language` is `nil` (the adapter detects it at runtime).
- NDS/GBA: first 3 chars of the 4-char game code select the game; the 4th char is the region: D=de, F=fr, I=it, S=es, E=en, P=en (EU English), J=ja, K=ko, others `nil`.
- `name` is a text identifier only; game names are read from the game at runtime.

## Interface `pokemon.core`

`core.interface.new(entry, detected, adapter)` builds the table for `fb.provide("pokemon.core", tbl)`. Convention for every method: a value, or `nil, "unsupported" | "not_ready" | <reason>`. All ids are the game's internal ids; names come from the user's own game text (current game language), never from tables. Contract version: v0.4 (adds the write helpers below; shared with the SoulLink plugin).

- `info()` returns `{ game_id, name, gen, system, version, language, revision, supported, features }`. `revision` is the game update (`"v1.0"` or `"v1.4"` for ORAS), not the region. `language` is `adapter:language()` (ORAS: MyStatus language byte as code `de en fr it es ja ko zh-Hans zh-Hant`) else the detected language. `features` has `team box location battle encounters badges trainer names areas locations live_stats icons map`: method-backed ones (`team`, `box`, `trainer`, ...) are true when the adapter has the method; an adapter refines the state-dependent ones through its optional `features()` (`icons` archive found, `map` scan finished, `names` game text loaded, `areas` zone scan found areas, `live_stats` live level/HP seen on a team member, `location`/`battle`/`encounters` address known).
- `team()`, `box(n)`, `box_count()`, `battle()`, `encounters()`, `badges()`, `trainer()`, `name(kind, id)`, `species_info(species, form)`, `areas()`, `locations()`, `zone_info(zone)`, `icon(species, form)`, `icon_variants(species, form)`, `map_candidates()`, `map_image(id)`, `map_selected()` delegate to the adapter method of the same name. Without adapter or method they return `nil, "unsupported"`; an adapter may return `nil, "not_ready"`, which is passed through.
- `team()` records: the generic record below plus live `level`, `hp`, `max_hp`, `status` (u32) from the live party stats (nil when the stats do not pass the sanity check; `level` then comes from EXP and the personal table) and `species_name` (nil until the game text is loaded). `slot` is the 1-based party position, only valid party members are listed.
- `location()` returns `{ zone = <u16 map/zone id>, location = <location name id or nil>, name = <string or nil>, x = <float?>, y = <float?>, source = "memory" }`; `nil, "unsupported"` when the revision has no map-id address, `nil, "not_ready"` while the address is unreadable.
- `badges()` returns `{ count = n, flags = { 8 booleans, index i = badge i } }`.
- `trainer()` returns `{ name, tid, sid, version, language, money, badges = n, play_time = { h, m, s } }` (money and play time are left out when implausible).
- `name(kind, id)` returns the string, `nil` for an unknown id, or `nil, "not_ready"` while the game text loads (`nil, "unsupported"` when no text archive is readable). `kind`: `species move item ability nature type location form`.
- `species_info(species, form)` returns `{ types = { t1, t2 }, growth }` (`t2 == t1` for a single type, type ids index `name("type", id)`), `nil, "not_ready"` while the personal table is unreadable, `"unknown_species"`, `"no_form"`.
- `areas()` returns the encounter areas in game order (first zone of the area): `{ id = <location name id>, name, zones = { zone ids with encounters }, encounters = { grass, tall_grass, swarm, surf, rock_smash, old_rod, good_rod, super_rod, horde } }`; each list holds `{ species, form, min, max }` (identical entries removed, empty lists absent). Only locations with at least one encounter slot are areas. `zone_info(zone)` returns `{ zone, location, name }` for any zone (towns included), `nil, "unknown_zone"` otherwise.
- `locations()` returns every location that has at least one zone (towns, routes, caves) in the order of its first zone: `{ id = <location name id>, name = <string or nil>, zones = { all zone ids }, has_encounters = bool }`; `nil, "not_ready"` while loading, `nil, "unsupported"`. Feature flag `features.locations`. Since 0.3.2 the zone list is only returned together with its names (while the game text loads: `nil, "not_ready"`), and when the zone scan is unsupported, failed or found no location, the list comes from the location text instead: every location id with a non-empty name, deduplicated by name (first id kept), in id order, `{ id, name, zones = {}, has_encounters = false, source = "text" }`, with `source = "text"` on the list too (`"zones"` otherwise, on list and entries). A failing zone scan is retried slowly instead of ending in a final `"unsupported"`; `areas()` then answers `nil, "not_ready"`.
- `diagnostics()` (0.3.2, feature flag `features.diagnostics`) -> flat table of plain numbers and strings, never names, for support reports: `zones_state` (idle scan done failed unsupported), `zone_files`, `zo_packs`, `zones_with_encounters`, `areas`, `locations` (zone-based count), `table_zones`, `zone_id_assignment` ("garc index" | "ordinal" | "none"), `first_rejection` (reason string or "none"), `zone_retries`, `text_state`, `text_language_index`, `text_retries`, `lines_<kind>` (species move type ability nature location item form), `species_file_index` (-1 when none), `revision`, `language`, `locations_source` ("zones" | "text" | "none"). Added in 0.3.3: `text_first_rejection`, `personal_ok`, `personal_attempts`, `personal_first_rejection`, `icons_state`, `icons_path`, `icons_count`, `icons_garc_ok`, `icons_garc_error`, `icons_first_rejection`, and per probed icon entry `icon_e1_*`, `icon_e25_*`, `icon_e700_*` with suffixes `first lz11 lz_failed size fmt w h px0`. Added in 0.3.4: per icon entry `layout` ("palette" | "plain16" | "none"), `head` (first 16 data bytes, hex), and for palette-signature data `count`, `pal` (first up to 8 palette u16, hex, comma separated), `idx` (first 8 index bytes, hex) and `idxbytes` (bytes left for the indices); and the map scan keys `map_state` (idle dirs files done failed unsupported), `map_archives_scanned`, `map_archives_total`, `map_archives_skipped`, `map_dirs_pending`, `map_entries_scanned`, `map_errors`, `map_candidates`, `map_current` (archive path or "none"), `map_first_rejection`, `map_fail_reason`, `map_steps`, `map_elapsed_ms`. `nil, "unsupported"` without adapter support.
- `battle()` returns `{ active = bool, kind = "wild" | "trainer", horde = bool, foes = { { species, form, level, hp, max_hp, shiny, personality, species_name } }, own = { { personality, species, hp, max_hp, slot, species_name } } }`; `{ active = false }` outside a battle. `encounters()` returns the last 64 wild encounters since the plugin started, oldest first: `{ seq, species, form, level, shiny, horde, zone, location, frame, species_name }`, one entry per wild battle start (horde: the first foe). Consumers remember the last `seq`.
- `icon(species, form)` returns a PNG string of the box icon, or `nil, "not_ready" | "unsupported" | "unknown_species"`; PNGs are cached in `fb.cache` (`icons/<species>-<form>-<rev>.png`, `rev` = `icons.CACHE_REV`, bumped when the decoding changes).
- `icon_variants(species, form)` (0.3.4, diagnostic aid) -> list of up to 5 `{ label, desc, png }` decodings of the same icon entry: `A` RGB565 + index 0 transparent + low nibble first, `B` RGBA5551 + low nibble first, `C` RGB565 + index 0 transparent + high nibble first, `D` RGBA5551 + high nibble first (palette readings, `gen6.pal_bclim`), `E` plain tiled RGBA5551 (only when the data is a plain 16-bit texture; then listed first: order E, A, B, C, D). Variants that cannot be decoded for the data are left out. `nil, "not_ready" | "unsupported" | "unknown_species"`; `unsupported` for non-palette, non-16-bit icons. Not cached.
- `map_candidates()` returns `{ {id, w, h}, ... }` (largest area first, at most 40) or `nil, "not_ready"` during the scan; `map_image(id)` returns the PNG (`nil, "not_ready" | "unknown_map" | "too_large"`, below 1 MiB); `map_selected()` returns the confirmed map id of the game or `nil`.

Write helpers (v0.4, ORAS; they build write operations and never write): all return `nil, "unsupported" | "not_ready" | <reason>` on failure, and on success `{ addr, bytes, ops = { {addr, bytes}, ... }, warnings = { ... } }` where `addr`/`bytes` are the first op; the caller applies the `ops` in order with `fb.memory.write` (permission `memory.write`, run rules and consent are the app's business).
- `encode_pokemon(location, fields)`: `location = { kind = "team", slot = 1..6 }` or `{ kind = "box", box = 1..31, slot = 1..30 }`. The current structure is read and decrypted, `fields` are applied, the checksum is recomputed and the result is encrypted again (the encryption constant is kept). `fields` (all optional): `species` (1..721; resets `form`, renames a not-nicknamed creature from the game's species name), `form` (0..31), `level` (1..100; EXP from the growth rate of the final species in the personal table, `growth_unavailable` when it cannot be read), `nature` (0..24), `ivs` / `evs` (partial tables with keys `hp atk def spe spa spd`, IV 0..31, EV 0..255, total at most 510 counting the untouched stats), `moves` (1..4 distinct ids 1..617, replaces the list), `pp` (per move slot, 0..64; unchanged moves keep their PP, new moves without `pp` get a placeholder of 5 and the warning `pp_unknown`), `shiny` (only the high half of the PID changes, so gender stays; uses the creature's own TID/SID), `held_item` (0..775, 0 = none), `ability` (1..191), `nickname` (up to 12 characters, empty = not nicknamed). Team slots with valid live stats also yield a second op for the live level/HP/stats area (slot +0x158, recomputed from the personal base stats; without readable base stats only the level changes and the warning `stats_stale` is returned); without valid live stats only the main block is written. Errors: `invalid_location`, `empty_slot`, `invalid_<field>`, `ev_total`, `unknown_field:<name>`, `growth_unavailable`.
- `encode_money(value)` (0..999999): op at `misc + 8` (u32).
- `encode_item(pocket, item, count)`: not implemented, always `nil, "unsupported"` (bag offsets are not documented here; none are guessed). Feature flag `edit_items` stays false.
- `edit_limits()` returns the validation limits (`species move item ability nature form level iv ev ev_total moves pp nickname money team_slots boxes box_slots`); `names_list(kind)` returns `{ {id, name}, ... }` from the game text (kinds as `name`), `nil, "not_ready"` while it loads. Feature flags `edit_pokemon edit_money edit_items name_lists`.

Generic Pokémon record (adapters fill what they can, unknown fields are `nil`; all IDs are the game's internal IDs, names come from the game, never from tables):

`{ species, species_name, form, nickname, level, exp, personality, shiny, gender, nature, ability, held_item, moves = {ids...}, ot_name, ot_id, ot_sid, language, egg, hp, max_hp, status, slot, box }`

## Events

Emitted through `fb.events.emit` (the source is this plugin's id): `game.detected` `{ game_id, gen, supported }` once; `team.changed` `{ team }` when the serialized team changed (checked every 15th tick); `battle.started` `{ kind, horde, foes = { species... } }`; `battle.ended` `{ kind }`; `encounter` (the new `encounters()` entry); `location.changed` (the `location()` table, emitted when zone, location id or name changed).

## Adapter contract

An adapter module exports `attach(ctx)` with `ctx = { fb = fb, game = entry, detected = info }`. It registers its memory watches and returns an adapter object with any of `revision() language() team() box(n) box_count() location() battle() encounters() badges() trainer() name(kind, id) species_info(species, form) areas() locations() zone_info(zone) icon(species, form) icon_variants(species, form) map_candidates() map_image(id) map_selected() diagnostics() features() tick() encode_pokemon(location, fields) encode_money(value) edit_limits() names_list(kind)`, called with `:` (the adapter is `self`). The adapter emits its own events (battle, encounter, location) through `ctx.fb.events`. Adapters read only through `ctx.fb`. `core.adapters` is a static registry keyed by module name; a missing module is skipped, so an entry without a usable adapter runs with `supported = false`.

## Entry

`main.lua`: unknown game logs `not_pokemon` and returns. Known game without adapter logs `no_adapter` and still provides the interface (`supported = false`). With an adapter: provide, emit `game.detected` once, every tick call the adapter's optional `tick()` (bounded background work and state tracking), then every 15th tick call `team()` and emit `team.changed` when its deterministic serialization (`core.serialize`) changed. All user-visible strings go through `fb.i18n.t` (`plugin/i18n/en.json` source, `de.json`); the v0.3 additions have no new UI strings (log lines are developer diagnostics in English).

## Adding a game

1. Add the entry to `core.games` (`GAMES`) and, for 3DS/NDS, the code to `plugin/manifest.json`.
2. Write the adapter `src/<genN>/<name>.lua` (contract above) plus synthetic-data tests.
3. Register it in `core.adapters` and add its modules to `src/modules.txt`; set `adapter` in the entry.
4. Document offsets and formats in `docs/games/<game>.md`; run `lua5.4 tools/bundle.lua`.

## Background discovery

Game text (`gen6.text`), zones (`gen6.zones`), icon (`gen6.icons`) and map (`gen6.maps`) discovery are state machines advanced by `adapter:tick()` on different tick phases (and by one step on a `not_ready` call). One step is one archive read, one directory listing, a bounded batch of GARC entries (8 zone entries) or, for the map scan, as many units (directory, archive open, 16 entries) as fit a 25 ms `fb.clock` budget, one text file or one candidate validation, so no entry call comes near the 500 ms / 20M instruction budget. Game text is loaded when the game language is known (fallback EN after about 300 steps, reloaded once the real language is known), the archive is dropped after its files are extracted and decoded lines are cached in memory only. Zones are kept as derived numbers in memory. Only icon and map results are persisted in `fb.cache` (`icons/index.txt`, `map/index.txt`, `map/files.txt`, `map/progress.txt`, PNGs); game text and names are never written to the cache.

State tracking in `tick()` (`gen6.oras`): revision detection (every 5th tick until found), `location.changed`, battle/encounter polling (`gen6.oras_battle`, every tick, reads only 232 bytes per opponent buffer until one changes) and the revision cross-check (every 30th tick until it had something to compare). All wrapped in `pcall`.
