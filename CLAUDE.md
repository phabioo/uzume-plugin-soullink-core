# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

uzume-plugin-soullink-core is the shared Pokémon foundation plugin. It detects the game (3DS title ID, later NDS/GBA/GB game codes), decodes the data structures in emulator memory (team, boxes, location, battle, encounters, badges; for Gen 6 including PKM decryption and shuffle), extracts assets from the player's own game files at runtime, and `provides` a generic Pokémon interface to other plugins (SoulLink, editor, cheats). It contains per-game adapters and no gameplay rules.

## Relation to Uzume

- Plugin for [Uzume](https://github.com/phabioo/uzume) (self-hosted retro gaming platform). Interface: `docs/architecture/12-plugins.md` and `docs/guides/plugin-api.md` in the Uzume repository.
- Plugin API v1 ships with Uzume since 0.11 (`docs/guides/plugin-api.md` there). Open API items are marked open, never invented.
- Runtime: Lua 5.4 in the Uzume sandbox; UI only as declarative building blocks (no QML).

## Working rules

- Repository language is English: code, comments, UI strings, docs, commit messages and PRs.
- Opus only orchestrates and writes no product code; implementation is done by the Sonnet 5.5 agents in `.claude/agents/`, searching and log reading by the Haiku agent `scout` (alias `haiku`).
- Briefs follow the template in `docs/workflow.md` (which also holds the token-saving rules).
- Opus verifies via `git diff --stat`, a targeted diff and the test result; commit/PR by Opus. One work package per thread, one topic per PR.

## Hard rules

- No ROMs, BIOS, firmware, game files, extracted assets, sprites, maps, text dumps or RAM dumps of real games in the repository or in tests. Tests use only synthetic data generated by code from documented formats.
- Nintendo/Pokémon names may appear as text identifiers only.
- Never put secrets in files, profiles or logs.
- Never overwrite saves silently.

## Languages

- Target versions are the German/EU releases first. Adapters support all language versions of a game where feasible, at least German and English.
- Names of species, moves, items and locations are read from the game at runtime so they appear in the game's language; they are never shipped as tables. Our own data tables are keyed by internal IDs, not names.
- Plugin UI strings come from i18n files (`i18n/`): English is the source, German the first translation.

## Status and commands

- Status: v0.4.2 (ORAS box icons: palette decoder variant D incl. 8-bit icons, measured icon order table, `info().icon_rev`); v0.4.1 (one-time icon debug export to the cache `diag/`, diagnostics key `icon_export`); v0.4.0 (plugin id uzume.soullink-core, interface `pokemon.core` unchanged); v0.3.5 (display name "SoulLink Core"); v0.3.4: game detection (Gen 3-7), the `pokemon.core` interface and the Omega Ruby/Alpha Sapphire adapter (team with live stats, boxes, trainer, badges, location with names, encounter areas, battle and wild encounters, game text, icons, region map candidates; 0.3.4: time-budgeted map scan that always ends in done/failed with `map_*` diagnostics, Lua icon decoder `gen6.pal_bclim` with `icon_variants`). Layout: `docs/architecture.md`.
- Sources are modules in `src/`; the sandbox has no `require`, so `lua5.4 tools/bundle.lua` generates the single `plugin/main.lua` (committed; list new modules in `src/modules.txt`). `lua5.4 tools/bundle.lua --check` fails when it is stale.
- Tests: `lua5.4 tests/run.lua` (fake `fb` in `tests/support/fb_mock.lua`, synthetic PK6 via `tests/support/pk6_*.lua`). CI runs both checks (`.github/workflows/ci.yml`).
- Packaging: `python3 -I tools/package.py [--out DIR] [--tag vX.Y.Z]` builds the unsigned `<id>-<version>.fbplugin` from `plugin/` (deterministic; `--tag` must equal the manifest version; `--verify FILE` validates structure). Release: `.github/workflows/release.yml` on `v*` tags (README, Releasing); CI also builds the package.
- The folder `plugin/` is what gets installed or linked in the Uzume developer mode.
- The SessionStart hook `.claude/hooks/session-start.sh` only prepares cloud sessions (installs `lua5.4` via apt if missing).
