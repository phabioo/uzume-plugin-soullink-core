# Roadmap

Status: in progress: skeleton and ORAS adapter; v0.6.0 (v0.5.0 plus the demo adapter, off by default, switched on by the plugin store key `dev.demo_data`); v0.5.0 (v0.4.2 plus write helpers for the Creature Editor, no memory writes inside this plugin); v0.4.2 (v0.4.1 plus correct ORAS box icons); v0.4.1 (v0.4.0 plus the one-time icon debug export); v0.4.0 (new plugin id `uzume.soullink-core`; v0.3.5 = v0.3.4 plus the display name "SoulLink Core"; v0.3.4 = v0.3.3 plus the time-budgeted map scan and the Lua icon decoder; v0.3.3 = v0.3.2 plus the Spanish language byte, LZ11 GARC entries, icon/text/personal diagnostics; v0.3.2 = v0.3.1 plus places that never stay empty: text fallback for `locations()`, names before lists, retried scans, `diagnostics()`; v0.3.1: fixes for zones and species names, and `locations()`) delivers live team stats, trainer/badges/money, location with names, encounter areas, battle state, wild encounters and names from the game text for Omega Ruby / Alpha Sapphire (v1.0 and v1.4); real-game verification of the derived and battle addresses is open (`docs/games/omega-ruby-alpha-sapphire.md`). Depends on Uzume plugin API v1 (since 0.11); see https://github.com/phabioo/uzume `docs/roadmap.md`.

## v0.1 Omega Ruby / Alpha Sapphire (3DS, Gen 6)

- Game detection by title ID, German/EU release first, German and English at least; detect the active game language at runtime (3DS system language), never assume it.
- Adapters: team, boxes, location, battle state, encounters, badges; PKM decryption/shuffle (Gen 6) with synthetic fixtures generated by code.
- Asset extraction from the player's own game files into the local plugin cache (box icons, sprites, region map); nothing is stored in this repository.
- Location/route table keyed by internal IDs, with self-recorded map coordinates; `provides` interface for other plugins.
- Offsets documented per game in `docs/games/<game>.md`; verified locally by the maintainer with the Uzume developer mode.

### Status v0.6.0 (demo data)

- v0.6.0: demo adapter (`demo.adapter`, `demo.data`) for live tests without a game: synthetic team of 3, one box creature, three zones (town, two routes with encounter areas), and a timeline at 30 ticks per second (10 s route 1, 15 s wild encounter, 20 s catch, 30 s route 2, 40 s trainer battle, 45 s faint of team slot 2, 50 s battle end, 60 s first badge). Names are synthetic ("Demomon N", "Demo Route 1"); icons are generated squares when `fb.codec.png` exists, otherwise `icon()` answers `nil, "unsupported"`. It runs only when the plugin store key `dev.demo_data` is `true` (the API has no per-plugin settings screen; set it with the MCP tool `store_put`, then restart the game). `info().demo` is `true`, `info().revision` is `"demo"`, `game.detected` carries `demo`. New permission `store`. No game memory is read in demo mode.

### Status v0.5.0 (ORAS)

- v0.5.0: PK6 encrypt, checksum and seal in `gen6.pk6` (pure Lua, same algorithm as `fb.codec.pk6_*`); `gen6.pk6_edit` (validation, EXP from level via the game's growth rate, nature, IVs/EVs with the 510 total, moves with PP, PID based shiny, held item, nickname, live party level/HP/stats recomputed from the personal base stats); `pokemon.core` gains `encode_pokemon(location, fields)`, `encode_money(value)`, `edit_limits()`, `names_list(kind)` and the feature flags `edit_pokemon edit_money edit_items name_lists` (contract v0.4, existing calls unchanged). The helpers only return write operations `{ addr, bytes }`; the Creature Editor plugin writes them with `fb.memory.write`.
- Open: `encode_item` (answers `nil, "unsupported"`; no bag/pocket offsets are documented in this repository, none were invented); PP of a newly chosen move (no move table is read: the caller passes `pp`, else a placeholder of 5 plus the warning `pp_unknown`); ability changes are not derived from the personal table (`ability` can be set by id, a species change warns `ability_unchanged`); personal base stat offsets 0x00-0x05 are PKHeX knowledge, not verified on a device; nothing here is verified on a real game.

### Status v0.4.1 (ORAS)

- v0.3.5: display name is now "SoulLink Core" (trademark avoidance) (manifest, i18n en/de, README); plugin id and interface unchanged (the id changed in 0.4.0).
- v0.4.2: ORAS box icons decoded as palette images (variant D, 4-bit and 8-bit indices, zero padding) and looked up through the measured icon order table (`gen6.icon_order`, numbers only); `info().icon_rev` lets consumers key their icon caches.
- v0.4.1: one-time debug export of raw icon GARC entries into the plugin cache (`diag/icon-<entry0>.bin`, `diag/icon-index.txt`) to settle whether the box icons are decoded wrongly or indexed wrongly; diagnostics key `icon_export`. Local to Fabio's PC, nothing enters the repository.
- v0.4.0: new plugin id `uzume.soullink-core` (Uzume ADR 0030 D7); no migration and no compatibility alias; the `provides` interface `pokemon.core` is unchanged.

- v0.3.4 (field report on a real Omega Ruby EUR v1.0, Player 0.15.7): (1) map scan: `step()` now runs units until a 25 ms `fb.clock` budget is used (was one unit per call, i.e. one 16-entry batch per 8 ticks), tiny entries are skipped without decompressing (LZ header size / GARC length), a throwing entry or archive is counted and skipped instead of ending the scan, the scan ends in `done` or `failed` (time limit 30 min, error limit) and `diagnostics()` has `map_*` keys; (2) icons: new `gen6.pal_bclim` (palette variants A-D, plain 16-bit texture E), `icon_variants(species, form)`, PNG cache key with decoder revision, `icon_e1_*` palette/layout diagnostics; format 7 data of exactly 64x32x2 bytes is a plain tiled RGBA5551 texture (a first pixel of 0x0002 matched the Player's palette signature); (3) the personal table is loaded by ticks (it was only loaded on demand, so `personal_attempts=0` was expected when the team carries live levels). Open: which icon variant matches the game (one constant, `pal_bclim.DEFAULT_VARIANT`), where the region map lives (no source), real-game confirmation.

### Status v0.3.3 (ORAS)

- v0.3.3: format audit fixes (2026-10-18): language byte 7 = Spanish (6 unused); GARC entries with first byte 0x11 are LZ11-decompressed in text, personal and icons through the shared `gen6.garc_entry` (zones and maps use it too); `diagnostics()` gains an icon archive probe (`icons_*`, `icon_e1/e25/e700_*`), `personal_*` and `text_first_rejection`; test GARCs use the real `CRAG` magic. Open: form icon index, Gen 6 palette BCLIM, real-game confirmation.

### Status v0.3.2 (ORAS)

- v0.3.2: `locations()` no longer stays empty (zone scan failed, unsupported or empty: every named line of the location text, `source = "text"`); lists are handed out only with names (a consumer caches the first list); failed archive opens and scans are retried slowly instead of ending in a final `unsupported` (zones and game text); new `diagnostics()` (counts, states, first rejection reason, no names). Real-game confirmation is open.

- v0.3.1: lenient ZO pack parsing (a bad offset no longer drops the pack), table-only zones, `locations()` (all places, towns included), the archive open is retried, species list found by content when file 98 is implausible, `species_name` on encounter records/events, diagnostics log lines (counts only). Real-game confirmation of the two fixed bugs is open.

- Done in code (synthetic tests): revisions v1.0/v1.4 with address overrides, live party stats, trainer/badges/money/play time, game text names, zones and encounter areas, `species_info`, battle/encounter tracking with events, region map scan with priority archives and noise filter.
- Open: verification on a real v1.0 game of the derived and battle addresses (Fabio), Alpha Sapphire, a non-guessed map coordinate table for the region map, encounter type detection (not in RAM).

## Later

1. Gen 7 (Sun/Moon, Ultra Sun/Ultra Moon): same 3DS formats, small step.
2. Gen 4 and 5 (NDS): NARC/NCGR containers, Gen 4/5 PKM.
3. Gen 3 (GBA) and Gen 1/2 (GB/GBC): the GB, GBC and GBA systems exist in Uzume since 0.13.

Gen 8 / Switch is out of scope. Requires plugin API v1 (since Uzume 0.11).
